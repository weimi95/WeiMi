微密文件 WeiMi · 更新日志v1.1.00

按时间倒序记录每一版改了什么，方便日后回看「某个功能是哪一版加的」。 下载最新版见官网首页。

  • v1.1.002026-10-20
    • 文件夹加密（单文件归档）：把整个文件夹打包成一个加密归档（扩展名 .wemi，容器格式 WEMI_FARC v1），用同一个口令保护；归档内的文件名与目录结构也加密（AES-256-GCM），外人拿到归档看不到里面有什么
    • 逐文件独立分块：归档内每个文件独立加密、大文件自动分块（桌面 256MB / 手机 128MB），单个文件损坏不会影响其余文件解包，且断点可续
    • 选择性解包：解密归档时可先「列出内容」，勾选其中部分文件单独解出，不必整包解压
    • 全链路入口：电脑端把文件夹拖进窗口即打包；手机端长按文件夹「加密文件夹」、点 .wemi 归档走解密/选择性解包；进度实时显示，底层复用 Rust 加密引擎（与单文件加密同一套 AES-256-GCM）
  • v1.0.722026-10-19
    • 例行发版：随「微密经典版（Win7/XP 客户端）」同期，主程序安装链路与启动稳定性加固
  • v1.0.712026-10-18
    • APK 安装链路修复，文件管理交互顺手度对齐
  • v1.0.702026-10-18
    • 飞传设备合并显示修复：开着 LocalSend 兼容时，同一台设备仍可能出现两条（一条「微密+LocalSend」+ 一条纯 LocalSend），个别情况下甚至只剩 LocalSend 条目——根因是合并后的微密条目已带链路，后续每条 LocalSend 广播都又新建了一条独立设备。现在微密设备永远优先，LocalSend 只作为链路挂在微密条目上，任何时序下同 IP 最多一条；手机端微密广播因省电延迟时，合并条目也不会被清掉
  • v1.0.692026-10-18
    • 双击 Ctrl 秒开浮窗：修复冷启路径约 0.5s 延迟——弹窗会话不再串行跑注册表写入、守护进程握手、飞传启动、索引加载等一整套常驻初始化，只保留必要项；UI 常驻时呼出也跳过了重复的窗口几何下发。按键检测本身 30ms 轮询不变
  • v1.0.682026-10-18
    • 设备列表合并显示：同一台手机同装微密 + LocalSend 两个 App 时，电脑端只显示一条设备（副标题「微密+LocalSend」），按 IP 自动合并双链路；只装真 LocalSend App 的对端仍正常单条显示
    • 文件夹发送：设备菜单新增「发送文件夹」，自研协议按相对路径传输、保留目录结构落盘；每个顶层目录在传输记录里汇总为一条。LocalSend 对端不支持目录（协议本身无此概念），会明确提示
    • LocalSend 兼容总开关：设置 → 微密飞传，默认开；关掉后不再广播/扫描 LocalSend 设备（隐私向兜底，不是显示开关）
    • 传输页「网页快传」卡片改名「微密飞传-网页版」
  • v1.0.672026-10-17
    • LocalSend v2 协议互通：与开源的 LocalSend App 互收互发文件（组播发现 + HTTP 传输双通道，Android 免原生代码）。协议考古级兼容：兼容新旧两代端点名、MIME 文件类型、对端默认 HTTPS 自签证书；本机恒明文
    • 防火墙放行范围扩到 LocalSend 端口（UDP/TCP 53317），老用户不会被误报
  • v1.0.662026-10-17
    • 保险箱「打不开报密码错」根治：真实根因是缓存临时目录被系统清理后无人重建（与密码无关），底层错误码分型专错专报，不再把所有失败翻译成「密码不正确」
    • 保险箱导入完成后询问是否删除原文件（保留/回收站/永久删除，可记住选择）
    • 电脑右键菜单 / 手机长按多选菜单补上「解密」项（此前只有加密）
  • v1.0.652026-10-17

  • v1.0.632026-10-17
