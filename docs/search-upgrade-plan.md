> 与原方案的差异：① size/dm/dc 不进索引，改「命中集二次 stat」（不动索引格式、

## 一、现状诊断（代码级根因）

| # | 问题 | 位置 | 现状 |
|---|------|------|------|
| 1 | **无排序策略** | `rust_crypto/src/lib.rs index_search` | 纯小写子串匹配，**按索引遍历顺序命中即收，凑满 300 条就截断**。搜 "4176" 时先扫到的一堆 hash 名 `.meta.json`/`.tmp` 占满名额，真正有用的排后面甚至被截掉 |
| 2 | 无通配符 | 同上 | 不支持 `*` `?`，也无"含通配符时按整个文件名匹配"语义 |
| 3 | 无运算符 | 同上 | 不支持 空格=AND、`\|`=OR、`!`=NOT、`<>` 分组、`"..."` 引号字面量 |
| 4 | 无匹配开关 | Dart 侧 | 无 区分大小写/全字匹配/匹配路径/正则/精准匹配 |
| 5 | 无宏/筛选器语法 | Dart 侧 | 主界面已有 FileCategory 筛选面板（file_filter_sheet），但不能在搜索框里用 `audio:` `ext:pdf` 这类语法，两者不通 |
| 6 | 无拼音搜索 | — | 中文文件名只能输中文搜；Listary/Everything1.5 用户习惯输拼音 |
| 7 | 无权重接口 | — | Everything 1.5 有 Weighted Search（官方 Help 收录），我们连排序基础都没有 |

索引新鲜度（watcher 实时增量 + USN sync + 5 分钟兜底重建）**不在本方案范围**，已可用。

## 二、目标排序模型（M1 核心，直接治截图病）

搜索改为「**全量命中 → 打分 → 取 Top N**」（打分只作用于命中集，通常几十~几千条，成本可控；不再"先到先得"截断）。

### 打分维度（初版权重，真机可调）

```
score = 命中质量 × 2^4 + 名称惩罚 + 行为加权
```

1. **命中质量（主导项）**，从高到低：
   - 文件名整体 = 查询词（去扩展名比对）→ 1000
   - 文件名以查询词开头 → 800（Everything/Listary 通用直觉：前缀最有用）
   - 词边界命中（`-`、`_`、空格、`.` 分隔后段首）→ 600
   - 文件名普通子串 → 400
   - 仅路径命中（文件名不含）→ 100
   - 多词 AND：每多命中一词加成；命中词数不足的条目直接淘汰
2. **名称质量惩罚（治哈希乱码）**：
   - 文件名含 ≥16 位连续 `[0-9a-f]` 十六进制串（哈希特征）→ −300
   - 扩展名命中临时/元数据黑名单：`.tmp .temp .meta.json .part .crdownload .partial` → −300
   - 文件名长度 > 64 字符 → 每超 32 字符再 −50（长 hash 串继续压）
   - 命中密度 = 命中长度 / 文件名长度，密度高者加分（短名精确命中 > 长名偶然命中）
3. **新近度轻加权**：Rust 侧 MTIMES 表已有，索引内存里查 mtime；7 天内 +30，30 天内 +10（防止"永远老文件压顶"，权重必须小，不能盖过命中质量）
4. **行为加权（后续增强，可独立一批）**：
   - 用户打开过的文件 +50/次（新增 open_history 落盘，Everything Run History 同思路）
   - 搜索历史里的词命中者微加

### 输出协议

`index_search` 返回顺序即最终排序（Rust 内排好），Dart 侧零改动兼容；另加 `index_search2` 保留能力：带 flags（大小写/全字/路径/正则/通配符模式）与 limit，供 M2 使用。

## 三、语法层升级（M2，对齐 Everything）

按 Everything 官方语法做**实用子集**：

| 能力 | 语法 | 说明 |
|---|---|---|
| 通配符 | `*` `?` | 含通配符时按**整个文件名**匹配（`*.mp3`、`foo*`）；无通配符维持子串语义 |
| 精准匹配 | `"abc def"` | 引号内按字面量（含空格），不走运算符 |
| AND | 空格 | `abc 123` |
| OR | `\|` | `*.jpg \| *.png`，`\|` 优先于 AND（与 Everything 1.4 默认一致） |
| NOT | `!` | `!backup` |
| 分组 | `<... ...>` | 后置批次（1.5 才有，价值中） |
| 修饰符 | `case:` `wholeword:` `path:` `regex:` | 词级前缀，覆盖菜单开关 |
| 函数 | `ext:pdf` `size:>100mb` `dm:today` | ext/size/dm(修改日期)/dc(创建日期) 优先；解析我们已有的 mtime，size 需索引补（MTIMES 旁加 SIZE 表或二次 stat，见取舍） |
| 宏 | `audio:` `video:` `image:` `doc:` `zip:` `exe:` `folder:` | 映射到已有 FileCategory 分类表，与筛选面板同源 |
| 拼音 | 输 `yinpin`/`yp` 命中「音频」 | 见 §六 取舍 |

正则用 Rust `regex` crate（需查 Cargo.toml 是否已依赖，未加则引入；`regex:` 时整串按正则、忽略其他通配符语义）。

## 六、关键取舍（需老板拍板）

1. **拼音搜索做不做**：做法是 Rust 侧建「文件名→全拼+首字母」别名表（内存约 ×1.5~2，100 万文件名多占几十 MB）或搜索时对中文候选实时转拼（慢但省内存）。推荐：**先做实时转拼**（只对含中文的命中集转，成本小），效果不满意再升级索引式。价值高（中文用户刚需）但非零成本。
2. **size 函数**：`size:` 需要文件大小进索引。推荐随 M2 在 Rust 索引结构里加 SIZE 表（build 时顺带 stat，增量同步时更新）——但要评估索引体积增幅（每条 +8 字节）。若嫌重，M2 先砍 `size:` 只留 `ext:`/日期。
3. **Everything IPC 后端**（上轮推荐的第一步）是否还要：现在自有索引新鲜度已解决，若本轮排序+语法到位，**Everything 依赖可降级为"以后有空再说"**——避免产品体验分裂（两套排序两种结果）。
4. **权重默认值**：我拟一版（见 §二），真机用你日常的搜索词调两轮再定稿。
5. **`<>` 分组与运算符优先级设置**：Everything 1.5 才有分组，1.4 用户其实用不到；建议先固定 `|` > AND，不做设置项（少一个开关，少一份文档负担）。

## 七、风险

- **打分回归**：排序改动的体感全在权重细节，需准备几组基准查询词（中文/英文/哈希噪音/通配符）真机对比。
- **FFI 协议变更**：`index_search` 语义从"命中即收"变"排序后输出"，返回格式不变（\n 分隔路径），但若 M2 加 flags 就走 `index_search2` 新入口，老入口保持兼容，Android 端不受影响。
- **性能**：全量打分在 200 万文件 × 多词查询时仍是 O(n) 单趟扫描 + 命中集排序，预期 <50ms；正则模式明确提示"慢"（菜单旁注）。
